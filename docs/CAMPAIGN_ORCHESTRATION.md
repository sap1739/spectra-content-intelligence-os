# Campaign Orchestration Architecture

**Phase 7D · ADR-0043.** How research becomes a campaign, and what refuses to happen along the way.

## 1. The run

One `CampaignOrchestrationRun` walks eight stages. The row is both the state machine and the audit
trail: each stage's status, note and timings are stored, so a run can be explained after the fact.

```
RESOLVE_INPUTS → SELECT_TRENDS → BUILD_STRATEGY → BUILD_PLAN
     → BUILD_CALENDAR → CREATE_ITEMS → GENERATE_DRAFTS → ROUTE_FOR_REVIEW
```

| Stage              | What it does                                                   | What can stop it             |
| ------------------ | -------------------------------------------------------------- | ---------------------------- |
| `RESOLVE_INPUTS`   | Loads the vertical or research project, and the brand          | `INPUTS_UNAVAILABLE`         |
| `SELECT_TRENDS`    | Explicit ids, or everything at/above `minTrendScore`           | `NO_TRENDS_SELECTED`         |
| `BUILD_STRATEGY`   | Derives objectives, pillars, personas, topics, platforms, CTAs | `ALL_ITEMS_BLOCKED`          |
| `BUILD_PLAN`       | Spreads writable topics across the window, one slot each       | —                            |
| `BUILD_CALENDAR`   | Creates (or adopts) the campaign and its window                | —                            |
| `CREATE_ITEMS`     | One `ContentItem` per slot, carrying its evidence lineage      | —                            |
| `GENERATE_DRAFTS`  | Writes each draft, grounded and cautioned                      | skipped, or per-item failure |
| `ROUTE_FOR_REVIEW` | Moves drafted items to `REVIEW`. Never schedules               | —                            |

## 2. The evidence gate

`assessEvidence` judges one topic from the sources behind it and returns a verdict, the action it
implies, and the numbers the verdict rests on — so a reviewer can check the reasoning rather than
trust a label.

```
sources ─┬─ ineligible (ADR-0030) ──────────────► excluded entirely
         ├─ none usable ────────────────────────► UNSUPPORTED  → BLOCK
         ├─ contradictions / contested ─────────► CONTRADICTED → CAUTION
         ├─ all snippet-only ───────────────────► SNIPPET_ONLY → CAUTION
         ├─ newest source > 180 days ───────────► STALE        → CAUTION
         ├─ < 2 publishers, or no verified claim► LIMITED      → CAUTION
         └─ otherwise ──────────────────────────► SUPPORTED    → ALLOW
```

Independence is counted by **publisher**, falling back to the source's host, so six articles from
one outlet are one source.

A cautioned topic does not merely carry a flag: `cautionGuidance` produces trusted operator-side
instruction that reaches the prompt via `additionalGuidance` — hedge, date the claim, attribute to
the snippet, or present the disagreement. The caution ends up in the writing.

## 3. The strategy engine

Deterministic and derived. Nothing is generated by a model.

| Artifact          | Derived from                                                                 |
| ----------------- | ---------------------------------------------------------------------------- |
| Objectives        | The funnel stages the campaign will cover, justified by the selected trends  |
| Pillars           | The vertical's keywords; a trend matching none becomes its own pillar        |
| Personas          | Workspace personas → the vertical's named audiences → a labelled placeholder |
| Topic ideas       | The selected trends × `itemsPerTrend`, each carrying its evidence verdict    |
| Funnel coverage   | The writable items, by stage                                                 |
| Platform strategy | The declared capability matrix + whether an account can actually publish     |
| CTA suggestions   | A fixed library keyed by funnel stage                                        |

Versioned as `spectra-strategy@1.0.0`. Everything the engine could not do is in `warnings`.

## 4. Lineage

Every created `ContentItem` carries `evidencePackId`, `researchProjectId`, `topicKey`, `findingIds`
and `citationIds` — the exact ids the gate saw, never assembled afterwards. The evidence pack's
`usedByContentItemIds` is updated in the other direction, so a pack knows what consumed it.

A run started from a **vertical** still records the research project its trends' evidence came from,
so lineage reaches the research either way.

## 5. Outcomes

| Status      | Meaning                                                                         |
| ----------- | ------------------------------------------------------------------------------- |
| `SUCCEEDED` | Everything planned was created and drafted; nothing was blocked or failed       |
| `PARTIAL`   | Some of it happened — blocked topics, failed drafts, or no generator configured |
| `FAILED`    | A stage could not complete; `failureReason` says which and why                  |
| `CANCELLED` | A person cancelled it, or the job was aborted                                   |

`PARTIAL` is the common case, and deliberately so. With no text-generation provider the run still
produces a real strategy, plan, calendar and evidence-linked items; only the prose is missing, and
each item says `GENERATION_UNAVAILABLE` with the reason.

## 6. Budget, idempotency, cancellation

- **Budget** — a `CONTENT_DRAFT` pre-flight runs before the run row exists, sized by the number of
  drafts the run would write. Refused campaigns leave nothing behind.
- **Idempotency** — `orchestrationRunKey` hashes the inputs that decide the output (trend ids and
  platforms order-independently). The same inputs adopt the existing run; a completed run is skipped
  on retry rather than rebuilt, keeping its campaign and items.
- **Cancellation** — checked between stages and before each draft, against the database as well as
  the abort signal, so a cancellation requested through the API stops a run already in flight.

## 7. What a run never does

- It never publishes, and never schedules. Drafted items go to `REVIEW`; a person approves and
  schedules them through the calendar, which already refuses unsupported targets.
- It never writes a topic the evidence does not support.
- It never invents a persona, a statistic or a source.
- It never reports a campaign it did not build.
